# 轻忆 · SillyTavern-LightMemory

面向长篇角色扮演的 SillyTavern 前端记忆扩展：按可调预算保留近期对话，分批整理旧内容，再按当前对话召回相关记忆。

**当前为 0.3.0 开发快照，尚未完成完整验收。** 开发基准为 SillyTavern 1.19.0、提交 `06bde939f`。请先在测试聊天中验证；详细进度见 [验证记录](TESTING.md)。

## 当前实现

- 近期上下文、最低回合数、整理阈值、摘要批次和注入预算可调。
- 记忆采集复用宿主上下文正则；正文预览用于检查实际采集结果，不采集独立 reasoning 字段。
- 分批摘要、历史概览、人物及别名、关系、物品、约定、伏笔和状态记录。
- 本地中文关键词召回；可选语义向量与关键词合并召回，服务失败时回退本地检索。
- 摘要连接可沿用主 API，或选择独立 OpenAI 兼容 API；独立密钥通过宿主管理，扩展保存密钥 ID。
- 每个聊天独立保存记忆及来源指纹，支持查看、编辑、固定、排除、导入和导出。
- 保留聊天存档原文，仅在生成请求中省略已整理且通过保存读回校验的旧内容。

这些是当前代码实现范围，不代表所有宿主、模型及服务组合均已实测通过。

## 安装与开始使用

在酒馆“扩展 → 安装扩展”中输入本仓库地址：

```text
https://github.com/demilich1117/SillyTavern-LightMemory
```

也可以在酒馆根目录执行：

```sh
git clone https://github.com/demilich1117/SillyTavern-LightMemory.git public/scripts/extensions/third-party/SillyTavern-LightMemory
```

也可下载仓库 ZIP，将包含 `manifest.json` 的目录放到对应的 `third-party` 目录。

刷新酒馆，在扩展设置打开“轻忆 · LightMemory”。先打开一个测试聊天，选择摘要连接，点击“测试摘要连接”。通过后再启用轻忆。默认不开启自动接管，启用轻忆后按“自动整理”设置执行。

独立 API 使用 Base URL、模型名和酒馆 Custom（OpenAI-compatible）密钥 ID。扩展不提供明文密钥输入框。主 API 首版代码适配 Chat Completion 与 Text Completion；其他类型可使用独立连接。

## 默认预算

摘要输出预留自 0.1.1 起默认 4,096 tokens；升级保留已有参数，不会自动把之前保存的 2,048 改掉。

| 参数 | 默认值 |
|---|---:|
| 近期上下文目标 | 12,000 tokens |
| 最低保留完整回合 | 4 轮 |
| 窗口外待整理文本阈值 | 4,000 tokens |
| 窗口外待整理回合阈值 | 8 轮 |
| 单批摘要输入目标 / 上限 | 4,000 / 6,000 tokens |
| 记忆注入预算 | 2,000 tokens |
| 最多召回条数 | 6 条 |

一次用户输入及随后角色回复算一轮；群聊同轮可包含多个角色回复。窗口外尚未整理的内容达到文本量或回合数任一阈值，即可触发整理。未完成整理与保存确认的正文继续交给酒馆处理。

近期目标只计算聊天内容，不包括预设、角色卡、世界书、其他扩展或长期记忆。宿主动态世界书等开销目前使用保守估算，酒馆执行最终上下文限制；最低回合数是软保护。实际窗口会随文本 token 数变化，不承诺固定保留多少条消息。

未知的独立模型或嵌入分词器采用保守估算，实际摘要输入还受 API 上下文和输出预留限制。向量服务首版接入 Transformers、OpenAI、硅基流动和 Ollama；切换模型或端点后应重建索引。

### 摘要输出被截断

0.1.1 起，收到 `finish_reason: length` 等输出上限标记时，会明确提示“摘要输出达到上限”，不会尝试补齐 JSON 或用独立思考内容替代正文。完整的 Markdown JSON 代码块仍可解析。

摘要输出预留的新默认值为 4,096 tokens；已有配置不会被覆盖。部分思考模型会将思考与最终 JSON 计入同一输出额度。遇到截断时，可在高级设置将输出预留调到 4,096 或 8,192；同时保证摘要上下文额度足够，实际输出预留最多为有效上下文的一半。提高输出预留会减少单批可用输入，插件会据此重新规划后续批次。必要时也可在服务商支持的配置中降低思考强度。

失败批次不会推进进度，调整参数后可以再次“整理历史”。扩展不会自动反复扩大额度重试。

## 后台摘要与聊天同时进行

0.2.0 新增“聊天时继续后台摘要”，默认开启。已经发出的摘要请求可以在角色回复期间继续；完成后等待聊天空闲，重新核对聊天身份、来源正文、正则清理结果及记忆版本，再保存并读回确认。当前角色回复继续使用之前已经确认的记忆，未整理的原文仍保留。

同一聊天依然一次整理一批，确保后一批概览接续前一批。不会同时发送多批摘要。聊天结束后再规划下一批，切换聊天、编辑来源或改变分支会取消或丢弃失效结果。群聊空闲检测有最多 10 分钟的等待上限。

摘要和聊天共用服务时，可能同时占用并发配额、触发限流或使响应变慢。独立摘要 API 可以分开安排连接；仅更换模型而仍共用同一账户配额，不一定消除限流。关闭该开关后，开始角色回复仍会取消后台摘要。后台指当前酒馆页面内运行，关闭或刷新页面不能保证任务继续。

## 悬浮快捷面板

默认显示一条收起的“轻忆”悬浮条，放在左侧，尽量避开常见的右侧工具。展开后显示整理楼层、已保存批数、耗时、待整理及近期轮次，并提供整理历史、暂停／恢复、查看记忆、上次注入和打开设置。

- 拖动“轻忆”标题调整位置，收起状态和位置记在当前浏览器；缩小窗口时限制在可见区域。
- 聚焦标题后用方向键移动，Home 复位；Esc 收起。
- “隐藏悬浮条”只隐藏面板，后台功能保持原设置；可在扩展设置重新勾选“显示悬浮条”。
- 角色正在回复时，暂停按钮显示“停止本次”，只取消当前后台任务，不影响本次聊天已准备好的记忆注入，也不关闭自动整理。
- 空闲时“暂停整理”会保存此聊天的暂停状态；“整理历史”可手动继续补齐。

## 结构化记忆（0.3.0）

新批次使用人物、事件、状态、任务四类结构。人物 ID（如 P001）由插件按聊天分配，名字、别名和昵称引用同一人物；别名可为空，不要求每张角色卡填写。同名人物不会自动合并，身份对应仍需摘要模型依据正文判断。分支保留已有批次中的 ID，各聊天的 ID 不跨存档共享。

- **事件 E001**：记录发生或明确陈述的内容、相关人物、来源楼层，区分明确证据与推测；历史事件留档。
- **状态 S001**：按人物与属性记录最后确认值。更新沿用原 ID，旧值留在历史批次中。例如持有物品或关系变化；回忆往事不应覆盖较新的状态。
- **任务 T001**：约定、待办、未解决事件沿用同一 ID，记录未开始、进行中、已完成、已取消或待核实。不能因后文没提到就认定完成。
- **剧情时间**：仅记录正文支持的日期或相对时间，并附参照楼层；时间不明就留空。不会用现实日期、楼层数推算过了几天。任务期限与完成事件时间分别记录。

每批按重要变化整理，通常约 4–8 项，不强求每类都有、不凑条数。模型输出 JSON，插件验证字段、引用、来源和状态更新依赖；无效批次不保存、不推进压缩。校验能检查结构一致性，不能证明自然语言内容属实，人物识别和摘要质量仍取决于模型。

注入模型时使用紧凑中文条目，同时显示人物名字与 ID。最后确认状态和任务进度单独列出，历史召回标明是过去的记录；所有内容共用原有注入预算，按相关性与额度选择。默认保留、批次和召回预算没有变化。摘要请求增加人物和状态登记表，计入 API 上下文预算；登记表过大时会减少可用批次输入，额度不足则保留原文并报错。

“查看记忆”顶部显示汇总的人物、状态和任务，下方保留各批历史。自由文本修改或排除某批后，该批及后续结构化汇总和概览停用，避免文字修改与旧字段冲突；历史记录仍保留，完整恢复需重建。

旧记忆可继续读取和召回，不自动猜测补人物 ID 或时间。新数据格式为 schema 2，兼容导入 schema 1；保存后不建议降级到旧版。若要让旧历史全部采用新结构，可先导出备份，再手动重建；重建会重新调用摘要 API，并替换手工整理结果。

## 数据与请求

全局配置存入扩展设置，记忆存入聊天元数据。摘要会发送清理后的正文与历史概览、人物与状态登记表至所选摘要服务；向量模式会将清理后的正文块发送至所选嵌入服务。本地关键词召回无需额外调用模型，但生成摘要仍需要摘要 API。

编辑、删除、swipe 或正则清理结果变化后，受影响记忆会失效，相关原文恢复保留。请通过“采集预览”确认预设中的思考、状态栏等内容确实被上下文正则排除。其他记忆扩展可能重复注入，轻忆不会自动修改它们的配置。

## 开发

原生 ES modules，无构建步骤或第三方运行时依赖。开发检查需要 Node.js 20 或更高版本：

```sh
npm test
npm run check
```

`src/core.js` 负责预算与记忆纯逻辑，`host.js` 隔离宿主接口，`engine.js` 调度任务，`vectors.js` 负责索引与语义召回，`ui.js` 提供中文面板。

当前仓库未指定开源许可证；上传开发快照不代表授予开源许可。后续正式发布时再明确许可证。
